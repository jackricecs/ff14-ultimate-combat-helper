# 05 机制站位提示（规划中，v0.6）

## 目标
你设定自己的职能（MT / ST / H1 / H2 / D1–D4），并选择一套打法（如"国服主流 / 某攻略组"）。出现某个机制时：
- **播报**：如"你是 D1：去 B 点外侧"；
- **悬浮窗**：显示场地示意图（俯视），高亮你的安全位置、当前头标/连线分配。

## 边界：只提示，不在游戏里"标点"
在游戏场地上自动放置标点（waymark）需要向游戏写入数据（例如鲶鱼精邮差那类注入/指令发送）。这超出本项目的只读原则，被检测或被举报时的后果也比只读工具严重得多，因此**不在本项目范围内**。本项目提供的是等效的"信息"：语音 + 悬浮窗示意图。如果你确实想要游戏内标点，那是另一个需要单独评估风险的项目。

## 为什么工作量大
机制解法高度依赖具体副本：需要识别头标（`27`，高难副本带偏移）、连线（`35`）、Debuff（`26`）、场地效果（`257 MapEffect`）、Boss 朝向/位置等，再按攻略规则求出每个人的位置。cactbot 的 raidboss 已经为当前高难副本写好了大量这类逻辑（含按职能的提示）。

## 实现路线
1. **复用而非重写**：优先让用户直接使用 cactbot raidboss，并提供"职能 + 打法"的用户配置；本项目补充 cactbot 没覆盖的打法分支。
2. **打法数据化**：定义 `strategies/<zoneId>/<打法名>.json`：机制 ID → 触发条件（日志行 + 正则/ID） → 每个职能的位置（场地坐标或 A/B/C/D/1/2/3/4 方位）+ 文本。
3. **攻略导入（AI 辅助）**：给定一篇攻略（文字 / RaidPlan 链接 / 图片说明），用大模型抽取为上面的 JSON **草稿**，在编辑界面中由人确认。AI 生成的站位必须人工审核后才能启用，因为站错位的代价是团灭。
4. **悬浮窗**：OverlayPlugin HTML 悬浮窗绘制场地图；插件通过 OverlayPlugin Addon 事件源推送"当前机制 + 我的位置"。

## 先决条件
- v0.4 的时间轴运行时（机制往往需要时间轴辅助定位）
- OverlayPlugin Addon 事件源（插件 → 悬浮窗通道）
